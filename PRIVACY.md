# Privacy

**English** · [Tiếng Việt](./PRIVACY.vi.md) · [中文](./PRIVACY.zh.md)

tally reads files that are already on your machine and does not send them anywhere.

## What it reads

| Path | What for |
|---|---|
| `~/.claude/projects/**/*.jsonl` | per-request **metadata, token counts and tool calls** |
| `~/.claude.json` | your plan tier and Claude Code's own credit constants |
| `~/.claude/cache/rate-limits.json` | current 5-hour / 7-day limit percentages |
| `~/.claude/cache/usage-cycle.json` | API-equivalent cost for the billing cycle |
| `~/.claude/usage-data/` | output of Claude Code's own `/insights` command |

## What it never reads

**Message text.** The parser (`src/ingest/parse.ts`) walks `message.content` to count `tool_use`
blocks and derive a few facts from them, then discards it. No message text, no assistant reply and
no file content ever reaches an event. The database schema has no column that could hold any of it.
Both facts are enforced by tests.

## What it keeps from a tool call

Reading is momentary; an index stays on disk, so what stays must be the minimum. From each tool call
tally stores only derived values:

| Kept | Example |
|---|---|
| tool name | `Bash`, `Read`, `mcp__playwright__browser_navigate` |
| shell verb | `grep`, `pnpm`, `git` |
| file extension | `ts`, `png` |
| last three path segments | `src/engine/behaviour.ts` |
| a count | `n = 42` |

**Never kept:** the raw command string, command arguments, file contents, URLs, or anything typed in
a message. Tests assert that a serialized fact does not contain the strings that were in the
original input.

This promise is narrower than the one tally made before derived facts existed, and it is stated
narrowly on purpose. "We do not read your conversations" would be a convenient way to describe
reading tool arguments, and it would be misleading.

## What it never does

- **No outbound network.** No telemetry, no analytics, no update checks, no CDN. The test suite
  scans every source file for outbound-capable calls, and an end-to-end test fails if the page
  requests any host other than `127.0.0.1`.
- **No writes to your Claude data**, except the `/insights` refresh you explicitly approve. The index
  lives in `~/.tally/`.

## The two things that cost you something

Both spend **your own Claude plan quota**, both ask first, and neither ever runs on page load.

| Action | What it runs | Cost |
|---|---|---|
| **Re-analyze** on the Insight page | `claude -p "/insights"` | measured at roughly 303 credits (about 0.15% of a 5-hour ceiling on Max 20x) and about 176 seconds |
| **Ask Claude to explain** | `claude -p` with the figures already on screen | a few KB of input; the page shows an estimate **measured from your own past headless runs**, and says "not measured" rather than showing a tidy number when it has fewer than 20 samples |

These are the only two write paths in the server: `POST /api/insight/refresh` and
`POST /api/explain/run`. Both require a token generated fresh on every server start and embedded
only in the locally served page, both reject `GET`, both run one at a time, and both print a line to
your terminal when they fire.

The explain action sends only the numbers the page is already showing, in the language and depth you
pick, to your own local `claude` binary. There is no third-party endpoint involved.

## Sharing screenshots

`tally serve --redact` replaces project paths with salted hashes, so grouping still works but
directory names are not shown. The screenshots in this repository were taken from synthetic data
generated by `scripts/make-fixture.mjs`, not from a real account.
