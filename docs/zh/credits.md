# Credit 与成本

tally 里并排放着两个数字，但它们的地位并不相同。

- **美元**由公开价目表算出，是精确的。
- **套餐 credit** 由一个 Anthropic 没有公开的公式算出。它是对着你本机上报的百分比拟合出来的，
  并且永远带着误差一起出现。

本页解释两者，以及 credit 那一侧拒绝装懂的四种方式。

---

## 美元：精确

每百万 token 的价格取自 Claude Code 的 `claude-api` skill，连同读取日期一起钉在
`src/data/pricing.ts`。缓存系数：

| 组成部分 | 相对输入价的倍数 |
| --- | --- |
| 5 分钟缓存写入 | 1.25x |
| 1 小时缓存写入 | 2x |
| 缓存读取 | 0.1x，个别模型有例外 |

算出来的结果与 `claude -p --output-format json` 上报的 `total_cost_usd` 做过对照，吻合到小数点后
第九位（`$0.356643` 对 `$0.356643`）。

表里没有的模型贡献 `$0`，**并且会说明这一点**，而不是悄悄套用邻近模型的费率。

---

## 套餐 credit：拟合出来的，并且会标注

### 常量从哪来

Claude Code 把自己的 credit 表存在 `~/.claude.json` 的
`cachedGrowthBookFeatures.tengu_amber_tally` 下：

```
credits = tokens / 1e6 × creditsPerMillionTokens[model]
fiveHourCredits = { default_claude_max_5x: 50000, default_claude_max_20x: 200000 }
```

tally 直接读这张表。对于没有这个键的机器，内置了一份回退表，`doctor` 会告诉你当前用的是哪一份。
**表里没有的模型就是没有**：它们显示 `n/a`，绝不显示 `0`。

### 被拟合的是什么

悬而未决的问题是*哪些 token 算数*。tally 尝试五个假设，挑出最能复现你客户端上报的
`five_hour_pct` 的那一个：

| 假设 | 计入的 token |
| --- | --- |
| `in_out` | 输入 + 输出 |
| `out_only` | 输出 |
| `in_out_write` | 输入 + 输出 + 缓存写入 |
| `in_out_write_read25` | 输入 + 输出 + 缓存写入 + 0.025 × 缓存读取 |
| `all` | 全部，缓存读取按全额计 |

默认是 `in_out_write_read25`。0.025 这个权重不是装饰：在推导它的那个窗口上，把缓存读取按全额计会
高估两个数量级，而能复现上报百分比的权重是 0.0269。1/40 是紧邻的整数，而且只在拟合认为它该出现的
地方使用。

`all` 被刻意排除在默认之外，它会把 credit 抬高几百倍。

### 四种拒绝

`calibrate()` 返回一个状态，页面把它印在数字旁边：

| 状态 | 含义 |
| --- | --- |
| `calibrated` | 某个假设在 15% 以内复现了上报百分比，误差会显示出来。 |
| `poor_fit` | 最好的假设仍偏差超过 15%，这些数字被标为仅供参考。 |
| `low_signal` | 用量不到上限的 5%，信号太少，无法拟合。 |
| `stale_index` | 索引比额度快照旧了五分钟以上，比较会系统性少算。它让你重建索引，而不是显示一个错的数字。 |
| `no_ceiling` | 读不到套餐上限，不做校准。 |
| `no_data` | 校准窗口里没有事件。 |

还有第五个标签，它不是状态：当某个 5 小时窗口远重于用来拟合的那个窗口时，会被标为**外推**，因为
在轻窗口上做的拟合对重窗口说明不了多少。

### 实测精度

在开发这台机器上，被选中的假设在所测的各个窗口里与上报百分比相差 **3% 到 9%**。这是诚实的区间，
不是对你账号的保证。

## 五项发现与三种"损失"

共检测五项发现，每项都折算成钱。关键细节是：它们的数字含义并不相同，所以每一项都带一个
`damage_kind`，页面对每种用不同的动词：

| 类型 | 使用的动词 | 例子 |
| --- | --- | --- |
| `saving` | "可以省下" | 本可以用 5 分钟写入的 1 小时缓存写入 |
| `spend` | "已经花掉" | subagent 过重的会话花了多少 |
| `peak` | "实测峰值" | 最重的 5 小时窗口相对上限的位置 |

这个区分之所以存在，是因为早期版本把一个实测峰值配上"损失"二字，结果读起来像是亏掉的钱。
配错动词的数字，是一句数值为真的谎话。

五项发现：

1. **1 小时缓存写入**价格是 5 分钟写入的 2 倍，要读三次才回本。
2. **缓存未命中**：你为重建而付钱的那次读取。
3. 跑在昂贵模型上的 **subagent 过重的会话**。
4. **模型过大**，用来回答不调用任何工具的短轮次。
5. **上限风险**：滚动的 5 小时窗口有多少次超过套餐上限的 80%。
